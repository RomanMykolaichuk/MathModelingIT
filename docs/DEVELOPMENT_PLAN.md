# План розроблення дисципліни

## Принцип

Розроблення ведеться не «по презентаціях», а по навчальних одиницях. Кожне заняття проходить однаковий цикл:

`методичний задум → математична модель → код → дані → експеримент → перевірка → завдання → матеріали викладача → презентація`.

## Етап 0. Базова інфраструктура репозиторію

Створити:

- структуру каталогів;
- `requirements.txt` / середовище;
- спільні utility-функції;
- правила іменування;
- шаблон notebook;
- шаблон README заняття;
- шаблон практичного завдання;
- шаблон презентаційного brief;
- базові перевірки запуску коду.

Рекомендована структура:

```text
MathModelingIT/
├── README.md
├── course_manifest.yaml
├── requirements.txt
├── docs/
├── common/
│   ├── plotting/
│   ├── data/
│   └── utils/
├── lessons/
│   ├── t1_l1/
│   ├── t1_l2/
│   ├── t1_l3/
│   ├── t1_l4/
│   ├── t2_l1/
│   ├── t2_l2/
│   ├── t2_l3/
│   ├── t2_l4/
│   ├── t2_l5/
│   ├── t2_l6/
│   └── t2_l7/
├── capstone/
├── presentations/
└── tests/
```

## Етап 1. Тема 1 — формування computational modeling mindset

### T1.L1 — Форма і принципи представлення математичних моделей

Код:
- параметрична функція `y=f(x, parameters)`;
- масові обчислення NumPy;
- побудова графіка;
- серія параметричних експериментів.

Результат: перший повний ланцюжок «формула → функція → експеримент → графік → висновок».

### T1.L2 — Класифікація математичних моделей

Код:
- детермінована модель;
- стохастична модель;
- дискретна динамічна модель;
- порівняння серій запусків;
- `random seed` як перше поняття відтворюваності.

Результат: один процес представлений моделями різних класів.

### T1.L3 — Організація математичного моделювання

Код та інфраструктура:
- читання даних;
- окремий модуль моделі;
- окремий script експерименту;
- збереження результатів;
- configuration/parameters;
- README дослідження.

Результат: маленький, але правильно організований research repository всередині заняття.

### T1.L4 — Класифікація методів математичного моделювання

Код:
- мініприклад чисельного методу;
- мініприклад Монте-Карло;
- мініприклад оптимізації;
- мініприклад мережевої моделі;
- матриця «problem → method → Python tool».

Результат: здатність обрати метод, а не просто бібліотеку.

## Етап 2. Тема 2 — інструментальні моделі

### T2.L1 — Задачі оптимізації в середовищі VS Code

Розробити:
- лінійну модель розподілу ресурсу;
- SciPy optimization example;
- PuLP або OR-Tools example;
- аналіз обмежень;
- сценарний запуск для різних запасів ресурсу.

### T2.L2 — Математична модель транспортної задачі

Розробити:
- CSV із джерелами, потребами та вартостями;
- модель balanced transportation problem;
- обробку незбалансованого варіанта;
- оптимальний план;
- heatmap/таблицю потоків;
- за можливості графову візуалізацію.

### T2.L3 — Математичні моделі задач нелінійного програмування

Розробити:
- нелінійну цільову функцію;
- різні стартові точки;
- constrained/unconstrained examples;
- contour plot;
- surface plot;
- демонстрацію локального мінімуму;
- короткий sensitivity experiment.

### T2.L4 — Математичне моделювання із застосуванням методів мережевого планування

Розробити:
- табличний опис робіт;
- DAG у NetworkX;
- CPM;
- критичний шлях;
- резерви часу;
- сценарій затримки;
- візуалізацію мережі.

### T2.L5 — Засоби розв’язування задач множинного вибору

Розробити:
- матрицю альтернатив;
- benefit/cost criteria;
- нормалізацію;
- Weighted Sum Model;
- TOPSIS;
- аналіз чутливості до ваг;
- візуалізацію ранжування.

### T2.L6 — Системи комп'ютерної математики та їх можливості для математичного моделювання

Розробити:
- SymPy equation solving;
- differentiation/integration;
- symbolic-to-numeric conversion;
- чисельну перевірку SciPy/NumPy;
- порівняння аналітичного та чисельного результату.

### T2.L7 — Використання систем комп’ютерної математики в наукових дослідженнях

Розробити інтеграційний notebook:
- research question;
- hypothesis;
- model assumptions;
- experiment configuration;
- batch experiments;
- statistical summary;
- sensitivity analysis;
- 2+ meaningful visualizations;
- reproducibility metadata;
- structured conclusion.

## Етап 3. Наскрізний capstone

Після реалізації окремих занять зібрати наскрізну модель у `capstone/`.

Рекомендований сценарій:

1. є декілька джерел обмеженого ресурсу;
2. є декілька пунктів потреби;
3. переміщення має вартість/час;
4. ефективність використання може бути нелінійною;
5. доставка складається з мережі робіт;
6. існує кілька альтернативних планів;
7. план оцінюється за кількома критеріями;
8. для ключових параметрів виконується sensitivity / Monte Carlo analysis.

Capstone не повинен бути прив’язаний до чутливих або реальних оперативних даних. Базова версія використовує синтетичні дані.

## Етап 4. Якість коду та відтворюваність

Для кожного lesson package перевірити:

- notebook запускається з чистого kernel;
- `.py` код не залежить від абсолютних шляхів;
- вхідні дані включені або генеруються;
- random seed зафіксований там, де потрібно;
- графіки відтворюються кодом;
- результати відповідають текстовому висновку;
- немає прихованих ручних операцій;
- requirements достатні для запуску.

Мінімальна автоматизація:

- smoke tests для Python-модулів;
- виконання ключових scripts у CI;
- перевірка імпортів;
- опціонально — виконання notebooks через `nbconvert`/`nbclient`.

## Етап 5. Презентації — тільки після стабілізації заняття

Для кожного завершеного заняття створюється окремий пакет:

```text
presentations/t1_l1/
├── PRESENTATION_BRIEF.md
├── NARRATIVE.md
├── assets/
├── generated_figures/
└── t1_l1.pptx
```

Порядок:

1. зафіксувати learning goal;
2. визначити 2 навчальні питання;
3. відібрати ключові математичні ідеї;
4. витягти графіки/таблиці з реального Python-коду;
5. сформувати narrative;
6. побудувати структуру слайдів;
7. створити презентацію;
8. перевірити читабельність формул, коду і графіків;
9. перевірити відповідність презентації практичному завданню.

## Рекомендований порядок фактичної розробки

1. T1.L1 — як еталонний lesson package.
2. T2.L1 — як еталон оптимізаційної практики.
3. T2.L2 — транспортна модель.
4. T1.L2–T1.L4 — закрити методологічну тему.
5. T2.L3–T2.L6 — інструментальні методи.
6. T2.L7 — інтеграційне дослідження.
7. Capstone.
8. По черзі створити 11 презентацій.

Такий порядок дозволяє рано перевірити стандарт заняття на двох принципово різних кейсах — простій параметричній моделі та повній оптимізаційній задачі — і лише після цього масштабувати шаблон на весь курс.
