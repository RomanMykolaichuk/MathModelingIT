# MathModelingIT

Навчальний репозиторій дисципліни з математичного моделювання для **ад’юнктів**.

## Поточний статус

- **11/11 офіційних занять:** `content_stable`;
- **підсумковий проєкт:** сформований і локально перевірений;
- **перевірка якості на рівні курсу:** автоматизований через GitHub Actions;
- **етап підготовки презентацій:** manifest фіксує згенерований початковий пакет; PPTX/ZIP не зберігаються у поточному дереві репозиторію;
- **пілот інтерактивних лабораторій:** розробляється окремий статичний інтерфейс у `web/` для GitHub Pages.

## Концепція

Дисципліна не перетворюється на окремий курс програмування Python. Python використовується як наскрізний інструмент реалізації та дослідження математичних моделей:

> **прикладна задача → математична постановка → формалізація → Python-модель → обчислювальний експеримент → візуалізація → інтерпретація → науковий висновок**

Офіційні назви тем і занять зберігаються. Змінюється внутрішня методика: від теоретичного розгляду моделей — до відтворюваного процес обчислювального моделювання.

## Цільова аудиторія

Ад’юнкти, для яких математичне моделювання має бути не лише навчальною дисципліною, а інструментом власного наукового дослідження.

## Основний результат навчання

Здатність формалізувати прикладну або наукову задачу у вигляді математичної моделі, обґрунтовано обрати метод її дослідження, реалізувати модель засобами Python, провести відтворюваний обчислювальний експеримент, проаналізувати й візуалізувати результати та сформулювати обґрунтований висновок.

## Структура розроблення

Репозиторій розвивається у двох пов’язаних, але окремих потоках:

1. **Навчально-обчислювальний контур** — зміст занять, Python-код, блокноти Jupyter, дані, завдання, результати та мініпроєкти.
2. **Презентаційний контур** — окремі презентації до кожного заняття, які створюються тільки після стабілізації змісту та практики відповідного заняття.

Окремо сформований **підсумковий проєкт**, який інтегрує калібрування, оптимізацію, незалежна перевірка, чутливість, невизначеність та відтворюваність metadata в одному мініпроєкт дослідження.

Докладніше:

- [`docs/COURSE_TASK.md`](docs/COURSE_TASK.md) — зафіксоване завдання на розроблення дисципліни;
- [`docs/DEVELOPMENT_PLAN.md`](docs/DEVELOPMENT_PLAN.md) — поетапний план реалізації;
- [`docs/LESSON_STANDARD.md`](docs/LESSON_STANDARD.md) — єдиний стандарт одного заняття;
- [`docs/PRESENTATION_WORKFLOW.md`](docs/PRESENTATION_процес.md) — окремий процес створення презентацій;
- [`docs/COURSE_QA.md`](docs/COURSE_QA.md) — перевірка якості на рівні курсу та контроль відтворюваності;
- [`course_manifest.yaml`](course_manifest.yaml) — перелік усіх 11 занять, підсумковий проєкт і поточний статус;
- [`capstone/`](підсумковий проєкт/) — підсумковий інтеграційний мініпроєкт дослідження;
- [`tools/course_smoke.py`](tools/course_smoke.py) — повна структурна, тестова та блокнот Jupyter-перевірка курсу.

## Принцип розроблення

Для кожного заняття спочатку формується методична й обчислювальна основа:

`lesson brief → model → notebook/code → experiment → expected outputs → verification → instructor notes`

і лише після цього:

`lesson content → slide narrative → presentation → visual QA`.

Це дозволяє підтримувати відповідність між математичною моделлю, кодом, практичним завданням і презентаційним матеріалом.

## перевірка якості на рівні курсу

Повна перевірка запускається командою:

```bash
python tools/course_smoke.py
```

GitHub Actions процес `.github/workflows/course-ci.yml` перевіряє:

- структуру всіх 11 пакети занять;
- усі заняття tests;
- виконання всіх `demo.ipynb`;
- підсумковий проєкт tests і блокнот Jupyter;
- відповідність manifest статусам `content_stable`.

До презентацій переходять тільки після проходження цього gate.


## MathModelingIT Lab — інтерактивний шар курсу

Каталог `web/` тепер є єдиним браузерним шаром для всіх 11 занять. Три лабораторії — **T1.L1, T2.L4, T2.L5** — мають повний інтерактивний цикл **Прогноз → Запуск → Пояснення → Перевірка меж → Перенесення**; решта занять представлені в мапа курсу і ведуть до Python пакети занять.

Платформа має режими **Слухач / Викладач**, локальне збереження прогресу та рефлексій, експорт JSON і накопичуваний паспорт моделі. Математичні функції винесені у `web/lab-engine.js`.

Ключовий принцип: Python/блокноти Jupyter залишаються еталонне джерело. Файл `web/control-cases.json` задає спільні контрольні сценарії, які Course CI перевіряє і через Node, і через Python (`tools/verify_web_control_cases.py`).

Докладніше: [`web/README.md`](web/README.md).


## MathModelingIT MiniBooks

Окремий каталог `books/` призначений для глибокого теоретичного шару курсу: **11 мінікниг — по одній на кожне заняття**.

Мінікнига не є розширеним README. Це самодостатній навчальний текст у напівхудожньому пояснювальному стилі:

> **військова проблемна сцена → інтуїція → формалізація → формули → графіки → обчислювальний експеримент → “зламай модель” → Lab → Python → Перенесення в дослідження**

Військові приклади мають бути синтетичними, неопераційними та без чутливих даних. Формули пояснюються словами, графіки інтерпретуються, а результати узгоджуються з Python еталонне джерело і заняття tests.

Єдиний стандарт усієї серії:

- [`books/TECHNICAL_SPEC.md`](books/TECHNICAL_SPEC.md) — технічне завдання на структуру, стиль, формули, графіки, Python-фрагменти, військові приклади, QA та Критерії готовності кожної мінікниги.

Після появи MiniBook відповідна кнопка **«Теоретичний матеріал»** у MathModelingIT Lab має вести на web-версію книги, а заняття README залишатиметься технічним паспортом заняття.
