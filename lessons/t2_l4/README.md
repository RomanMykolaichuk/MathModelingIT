## 1. Problem

Проєкт складається з взаємозалежних робіт. Простого переліку тривалостей недостатньо: важливо врахувати, які роботи можуть виконуватися паралельно, які мають передумови і які реально визначають строк завершення всього проєкту.

Дослідницькі питання:

- які роботи формують мінімально можливий строк завершення проєкту;
- які роботи мають резерв часу;
- яка затримка є критичною, а яка може бути поглинута резервом;
- як змінюється висновок, якщо тривалості робіт невизначені;
- яка ймовірність завершити проєкт до заданого строку.

## 2. Математична модель CPM

Проєкт представляється орієнтованим ациклічним графом `G=(V,E)`, де `V` — роботи, `E` — відношення передування.

Для кожної роботи `i` із тривалістю `d_i` визначаються:

- `ES_i` — earliest start;
- `EF_i = ES_i + d_i` — earliest finish;
- `LF_i` — latest finish;
- `LS_i = LF_i - d_i` — latest start;
- `Slack_i = LS_i - ES_i`.

Робота є критичною, якщо `Slack_i = 0`.

Критичний шлях — найдовший за тривалістю шлях від початку до завершення мережі. Його довжина визначає мінімальну тривалість проєкту.

## 3. Базова мережа

| Task | Duration | Predecessors |
|---|---:|---|
| A | 4 | — |
| B | 3 | — |
| C | 5 | A |
| D | 4 | A |
| E | 6 | B, C |
| F | 3 | D |
| G | 2 | E, F |

Контрольний результат:

- тривалість проєкту: **17**;
- критичний шлях: **A → C → E → G**;
- резерв B: **6**;
- резерв D: **4**;
- резерв F: **4**.

## 4. Delay experiment

### Сценарій 1 — затримка критичної роботи

`C: +3`

Результат:

- проєкт: **20**;
- критичний шлях залишається `A → C → E → G`.

### Сценарій 2 — затримка некритичної роботи

`D: +3`

Її початковий резерв дорівнює 4, тому тривалість проєкту залишається **17**.

> Затримка окремої роботи не тотожна затримці всього проєкту. Наслідок залежить від місця роботи в мережі та доступного резерву.

## 5. PERT

Для невизначеної тривалості задаються `a` — optimistic, `m` — most likely, `b` — pessimistic.

Класична PERT-оцінка:

`E(T) = (a + 4m + b) / 6`

`Var(T) = ((b-a)/6)^2`

Файл `data/pert.csv` містить три оцінки для кожної роботи.

## 6. Monte Carlo extension

Для кожної роботи генерується тривалість із Beta-PERT розподілу. Для кожної реалізації:

1. формуються тривалості всіх робіт;
2. повторно розраховується CPM;
3. зберігається тривалість проєкту;
4. зберігається критичний шлях.

Baseline Monte Carlo:

- `n = 3000`;
- `seed = 2026`;
- mean project duration ≈ **17.86**;
- P90 ≈ **19.69**;
- `P(T <= 19) ≈ 0.79`;
- домінуючий критичний шлях — `A → C → E → G`.

## 9. Interpretation

Ад’юнкт має пояснювати:

- чому саме певний шлях критичний;
- чому zero slack є важливішим за просто «довгу роботу»;
- коли резерв перестає поглинати затримку;
- чому PERT/Monte Carlo не гарантує фактичний строк;
- як модель залежить від якості оцінок `a, m, b`;
- чому критичний шлях у stochastic model може змінюватися між реалізаціями.
