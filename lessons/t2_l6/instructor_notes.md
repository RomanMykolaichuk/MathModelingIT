# Instructor notes — T2.L6

## Центральна ідея

Заняття не повинно перетворюватися на огляд команд SymPy. Основна теза:

> **Система комп'ютерної математики корисна тоді, коли допомагає досліднику переходити між математичною структурою, аналітичним перетворенням, чисельним експериментом і перевіркою.**

## Рекомендована логіка проведення

### 1. Проблемне питання

Показати дві ситуації:

- формула отримана вручну, але потрібно перевірити й дослідити параметри;
- аналітичного розв'язку немає або він незручний — потрібен чисельний метод.

Запитати:

> Чи є SymPy альтернативою SciPy?

Очікувана відповідь: **ні; вони виконують різні, але взаємодоповнювальні ролі**.

### 2. Запис моделі

Ввести

\[
dS/dt=q-kS.
\]

До коду проговорити:

- стан;
- параметри;
- початкову умову;
- одиниці вимірювання;
- припущення.

### 3. Символьний блок

Продемонструвати:

- `symbols`;
- `Function`;
- `Eq`;
- `solve`;
- `diff`;
- `integrate`;
- `simplify`.

Не демонструвати команди ізольовано — кожна має відповідати конкретному дослідницькому питанню.

### 4. Verification

Особливо акцентувати residual:

```python
simplify(dSdt - rhs)
```

Якщо результат нуль — формула задовольняє рівняння символічно.

### 5. Lambdify

Пояснити, що `lambdify` — міст між комп'ютерною алгеброю і масовими чисельними обчисленнями.

### 6. Незалежна чисельна перевірка

Запустити `solve_ivp` і накласти три траєкторії:

- closed form;
- lambdified SymPy;
- SciPy.

Поставити питання:

> Якщо вони збігаються, що саме ми перевірили?

Правильна відповідь: узгодженість реалізацій для цієї математичної моделі, але не її адекватність реальному об'єкту.

### 7. Sensitivity

Показати:

\[
\partial(q/k)/\partial k=-q/k^2.
\]

Потім зіставити символьний знак похідної з чисельною таблицею.

Це важливий зв'язок:

**symbolic sensitivity → computational experiment → interpretation.**

## Типові помилки

1. Плутати `solve` та чисельну оптимізацію.
2. Вважати великий символьний вираз автоматично корисним.
3. Не задавати припущення для символів.
4. Використовувати `evalf()` там, де потрібна функція для масивів.
5. Не перевіряти результат незалежним способом.
6. Робити висновок про реальну систему лише з математичної тотожності.

## Дискусійні питання

1. Коли closed-form solution є перевагою?
2. Коли аналітичний вираз стає практично менш корисним за чисельний solver?
3. Чим symbolic verification відрізняється від validation моделі?
4. Чи можна використовувати SymPy для sensitivity analysis до запуску Monte Carlo?
5. Які елементи дисертаційної моделі варто залишати символьними?

## Очікуваний висновок ад'юнкта

> Символьний і чисельний підходи не конкурують. Символьний рівень допомагає дослідити структуру моделі та отримати загальні залежності; чисельний — виконувати масштабні обчислення, працювати з моделями без зручного closed-form solution та перевіряти результати незалежним способом.
