# Instructor Notes — T1.L1

## Роль заняття в дисципліні

Це еталонне заняття, яке вводить наскрізну логіку всього курсу:

**problem → mathematical model → Python model → experiment → visualization → interpretation → research transfer.**

Не слід перетворювати заняття на вступ до синтаксису Python. Код тут виконує роль формального і виконуваного представлення моделі.

## Основна методична теза

Потрібно розвести три поняття:

1. **реальна система**;
2. **математична модель системи**;
3. **програмна реалізація математичної моделі**.

Python-код не є самою реальною системою і не є тотожним математичній моделі. Це реалізація, яка дозволяє провести обчислювальний експеримент.

## Рекомендована логіка пояснення

### Крок 1. Словесна задача

«Є запас ресурсу, який рівномірно витрачається».

Не показувати формулу одразу. Запитати:

- що є змінною;
- що є параметром;
- що ми хочемо отримати на виході.

### Крок 2. Формула

Після відповідей перейти до `S(t)=S0-vt`.

Поставити питання: «Чи є ця формула вже хорошою моделлю?»

### Крок 3. Провокаційний приклад

Для `S0=100`, `v=5`, `t=30` формула дає `-50`.

Це корисний момент для обговорення:

> математично правильне обчислення може бути змістовно неправильним.

Після цього ввести обмеження `S(t) >= 0`.

### Крок 4. Python-функція

Спочатку показати простий варіант:

```python
def resource(t, s0, rate):
    return max(0, s0 - rate * t)
```

Потім перейти до навчального `src/model.py`, де є робота з масивами та валідація.

### Крок 5. Сценарний експеримент

База: `S0=120`, `rate=8`.

Запитайте прогноз до запуску коду:
- коли ресурс вичерпається;
- якою буде форма графіка.

Після цього запускається код.

### Крок 6. Зміна параметра

`rate=5`.

Важливе питання:

> Ми змінили модель чи лише сценарій?

Правильна відповідь: структура моделі залишилася тією самою; змінився параметр сценарію.

### Крок 7. Чутливість

Порівняти `rate=[4,6,8,10,12]`.

Пояснити різницю між:
- одиничним розрахунком;
- сценарним експериментом;
- аналізом чутливості.

## Питання для дискусії

1. Чим математична модель відрізняється від формули?
2. Коли додаткове ускладнення моделі виправдане?
3. Чи завжди більш точна модель є кращою?
4. Що означає «адекватність моделі»?
5. Які припущення треба обов’язково фіксувати у науковій роботі?
6. Чи можна робити управлінський висновок з моделі, не перевіривши її область застосовності?

## Типові помилки ад’юнктів

- починати з коду замість дослідницького питання;
- використовувати змінні без змістовного визначення;
- не розділяти параметр і змінну;
- приховувати припущення;
- вважати графік доказом;
- описувати лише значення, не інтерпретуючи їх;
- робити висновки поза областю застосовності моделі;
- ускладнювати модель без потреби.

## Research transfer

Після практики дати 5–7 хвилин на власну постановку. Не оцінювати складність математики; оцінювати коректність структури:

- що досліджуємо;
- які змінні;
- які параметри;
- яке припущення;
- що змінюємо в експерименті;
- що вимірюємо;
- як перевіряємо.

Це створює місток між навчальною моделлю та дисертаційним дослідженням.
