# Практичне завдання T1.L3

## Організація відтворюваного computational experiment

### Мета

Перетворити просту математичну модель на структурований дослідницький workflow, який можна повторно запустити, перевірити й пов’язати з конкретними умовами експерименту.

## Частина 1. Відтворіть baseline

1. Встановіть залежності з `requirements.txt`.
2. Запустіть:

```bash
python -m lessons.t1_l3.src.experiment
```

3. Переконайтесь, що створено:
   - `outputs/results.csv`;
   - `outputs/summary.csv`;
   - `outputs/metadata.json`.
4. Зафіксуйте `experiment_id`.

Контрольне значення:

```text
t1_l3_0c5d08ed47eb
```

для незміненої базової конфігурації.

## Частина 2. Verification

Покажіть ручний розрахунок:

\[
Y=20+1.8\cdot40-1.2\cdot50=32.
\]

Перевірте, що Python-модель повертає те саме значення.

Запустіть:

```bash
pytest lessons/t1_l3/tests -q
```

Очікувано: `9 passed`.

## Частина 3. Змініть config, а не model.py

Створіть власну конфігурацію:

- змініть `replications`;
- змініть `noise_sd`;
- не редагуйте математичну функцію без окремого обґрунтування.

Поясніть:

1. які зміни є зміною **експерименту**;
2. які зміни були б зміною **самої моделі**.

## Частина 4. Додайте два сценарії

До копії `scenarios.csv` додайте щонайменше два сценарії.

Умова:

- один сценарій змінює `resource`;
- другий змінює `load`.

Проведіть експеримент і порівняйте:

- deterministic response;
- mean observed;
- std observed;
- p10;
- p90.

## Частина 5. Reproducibility test

1. Запустіть один і той самий config двічі.
2. Порівняйте `results.csv`.
3. Змініть тільки seed.
4. Повторіть запуск.
5. Поясніть, чому:
   - raw observations змінилися;
   - загальна статистична поведінка може залишатися близькою.

## Частина 6. Git traceability

У звіті наведіть:

```text
experiment_id:
config_hash:
seed:
Git commit:
input data:
output files:
```

Якщо робота виконується локально без commit, вкажіть це як обмеження відтворюваності.

## Частина 7. Research transfer

Опишіть один реальний або синтетичний computational experiment для власної дисертації:

### Research question
Що саме перевіряється?

### Input data
Звідки беруться дані?

### Model
Яка формальна залежність або алгоритм?

### Config
Які параметри мають бути винесені з коду?

### Scenarios
Що змінюється між експериментами?

### Verification
Як перевірити коректність?

### Outputs
Які таблиці/метрики/графіки потрібні?

### Metadata
Що необхідно зафіксувати, щоб відтворити результат?

## Що подати

1. виконаний `practice.ipynb`;
2. власний config;
3. власний scenarios CSV;
4. summary результатів;
5. metadata;
6. короткий висновок;
7. research transfer.
