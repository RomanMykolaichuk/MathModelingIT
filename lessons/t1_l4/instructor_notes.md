# Instructor notes — T1.L4

## Головна педагогічна ідея

Не викладати заняття як довідник бібліотек. Центральне питання:

> Яка структура задачі підказує метод?

## Рекомендований хід

1. Дати 6 постановок без назв методів.
2. Попросити ад’юнктів класифікувати очікуваний тип результату.
3. Лише після цього співвіднести задачу з методом.
4. Показати мінімальний Python-код.
5. Провести verification або sanity check.
6. Обговорити, що зміниться, якщо змінити постановку.

## Контрольні результати

- numerical root для `120 - 6t - 0.2t^2 = 0` має збігатися з позитивним symbolic root;
- лінійна оптимізація повинна дотримуватися обох обмежень;
- Monte Carlo probability має бути в `[0,1]` і бути ідентичною за того самого seed;
- critical path: `Start → A → C → Finish`, довжина `12`;
- MCDA має повертати впорядкований рейтинг.

## Питання для дискусії

- Якщо SymPy дає точне рішення, навіщо SciPy?
- Якщо задача має випадковість, чи можна просто використати середні значення?
- Коли оптимізаційна модель стає некоректною, хоча solver повертає `success`?
- Чи може найкоротший шлях бути критичним шляхом?
- Чи є ваги MCDA об’єктивними даними?

## Типові помилки

1. Вибір бібліотеки до формалізації задачі.
2. Змішування симуляції та оптимізації.
3. Інтерпретація Monte Carlo probability як універсальної істини.
4. Ігнорування напрямку критеріїв cost/benefit у MCDA.
5. Відсутність незалежної перевірки результату.
